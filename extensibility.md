# ACP v1 uses `_meta` and underscore methods for extensions, with completed guidance for propagating correlation metadata.

**Stable v1.** A protocol type may carry custom information only when it defines `_meta: { [key: string]: unknown }`; this applies to many requests, responses, notifications, content blocks, tool calls, plan entries, and capability objects, but not every type—`Error` is an explicit counterexample ([Stable v1 extensibility, lines 1–7](https://agentclientprotocol.com/protocol/v1/extensibility)). Implementations must not add custom fields beside specified root fields because those names are reserved for future protocol versions; inside `_meta`, `traceparent`, `tracestate`, and `baggage` should remain reserved for trace interoperability ([Stable v1 extensibility, lines 8–16](https://agentclientprotocol.com/protocol/v1/extensibility)).

```json
{"_meta":{"example.com/feature":{"enabled":true}}}
```

ACP reserves JSON-RPC method names beginning with `_` for extensions. A custom request has an `id` and expects a response; a custom notification omits `id` and is one-way ([Stable v1 extensibility, lines 20–31](https://agentclientprotocol.com/protocol/v1/extensibility)). Unrecognized custom notifications should be ignored, while extension support should be advertised through `_meta` on capability objects so callers can check before use ([Stable v1 extensibility, lines 35–49](https://agentclientprotocol.com/protocol/v1/extensibility)). See [initialization](initialization.md) for capability negotiation, plus [content blocks](content-blocks.md) and [tool calls and permissions](tool-calls-and-permissions.md) for nested types that can carry `_meta`.

**Completed RFD, reflected in stable v1.** The meta-propagation RFD required the extensibility specification to define `_meta` and document propagation ([Meta-propagation RFD, lines 17–21](https://agentclientprotocol.com/rfds/meta-propagation)). Its convention lets clients propagate correlation fields such as `requestId` to agents while reserving root `_meta` keys `traceparent`, `tracestate`, and `baggage` for W3C trace context ([Meta-propagation RFD, lines 38–42](https://agentclientprotocol.com/rfds/meta-propagation)). Compatible ACP and MCP `_meta` fields allow shared instrumentation ([Meta-propagation RFD, lines 48–52](https://agentclientprotocol.com/rfds/meta-propagation)). The revision history records implementation in the extensibility docs on 2025-12-04 and completion on 2026-06-03 ([Meta-propagation RFD, lines 57–61](https://agentclientprotocol.com/rfds/meta-propagation)).
