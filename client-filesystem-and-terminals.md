# Clients expose files and terminals so agents act through the user’s environment.

ACP v1 gates file access through `clientCapabilities.fs.readTextFile` and `.writeTextFile`; an agent MUST NOT call a missing or false capability ([File System, lines 4–25](https://agentclientprotocol.com/protocol/v1/file-system)). `fs/read_text_file` takes `sessionId`, absolute `path`, optional one-based `line`, and optional maximum-line `limit`; it returns string `content` and can include unsaved editor changes ([File System, lines 27–79](https://agentclientprotocol.com/protocol/v1/file-system)). `fs/write_text_file` takes `sessionId`, absolute `path`, and string `content`, returns an empty result, and makes the client create a missing file ([File System, lines 85–131](https://agentclientprotocol.com/protocol/v1/file-system)). Client ownership therefore preserves live editor state and lets the editor track agent modifications ([File System, line 1](https://agentclientprotocol.com/protocol/v1/file-system)).

Terminal calls require `clientCapabilities.terminal`; false or absent means the agent MUST NOT call them ([Terminals, lines 3–10](https://agentclientprotocol.com/protocol/v1/terminals)). `terminal/create` takes `sessionId`, `command`, optional string-array `args`, `{name,value}` environment entries, absolute `cwd`, and `outputByteLimit`, returning a `terminalId`; overflow drops earliest output at a character boundary ([Terminals, lines 13–48](https://agentclientprotocol.com/protocol/v1/terminals)). The other requests take `sessionId` and that `terminalId` ([Terminals, lines 60–117](https://agentclientprotocol.com/protocol/v1/terminals)). `terminal/output` returns `output`, `truncated`, and optional `exitStatus` (`exitCode`, `signal`) without blocking; `terminal/wait_for_exit` blocks and returns `exitCode` and `signal` ([Terminals, lines 60–89](https://agentclientprotocol.com/protocol/v1/terminals)). `terminal/kill` and `terminal/release` have no result fields ([Terminals, lines 91–117](https://agentclientprotocol.com/protocol/v1/terminals)). Kill terminates but preserves output/status access and still requires release; release kills a running process, frees resources, and should not erase embedded output from the client display ([Terminals, lines 91–99](https://agentclientprotocol.com/protocol/v1/terminals); [lines 113–117](https://agentclientprotocol.com/protocol/v1/terminals)).
