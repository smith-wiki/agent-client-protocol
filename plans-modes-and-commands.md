# Stable ACP v1 prefers configuration options while plans and slash commands remain dynamic session updates.

**Plans.** An agent **SHOULD** report a plan with `session/update` as `{"sessionUpdate":"plan","entries":[{"content":"Inspect logs","priority":"high","status":"pending"}]}`. Each entry requires human-readable `content`, `priority` (`high|medium|low`), and `status` (`pending|in_progress|completed`). ([Agent plan, lines 3–44](https://agentclientprotocol.com/protocol/v1/agent-plan)) Every update **MUST** carry the complete list; the client replaces its plan, although the agent may add, remove, or modify entries. ([Agent plan, lines 46–59](https://agentclientprotocol.com/protocol/v1/agent-plan))

**Modes (legacy).** Initial `modes` is `{currentModeId,availableModes:[{id,name,description?}]}`: `id` and `name` are required; `description` is optional. ([Session modes, lines 6–45](https://agentclientprotocol.com/protocol/v1/session-modes)) A client calls `session/set_mode` with `sessionId` and a listed `modeId`; an agent announces self-changes as `{"sessionUpdate":"current_mode_update","currentModeId":"…"}`. ([Session modes, lines 47–71](https://agentclientprotocol.com/protocol/v1/session-modes)) Dedicated mode methods are slated for removal and remain alongside config options only for backward compatibility. ([Session modes, lines 1–3](https://agentclientprotocol.com/protocol/v1/session-modes))

**Configuration (current).** `configOptions` supersedes modes; transition agents should send both, use `category:"mode"`, and keep them synchronized. ([Config options, lines 179–192](https://agentclientprotocol.com/protocol/v1/session-config-options)) An option has required `id`, `name`, `type`, `currentValue`; optional `description`, `category`; and `options` only for `select`. `select` uses string value IDs; `boolean` requires advertised `clientCapabilities.session.configOptions.boolean` and a Boolean value. ([Config options, lines 20–64](https://agentclientprotocol.com/protocol/v1/session-config-options)) `session/set_config_option` takes `sessionId`, option `id`, and valid `value`, then returns complete state; agents can emit `config_option_update`. ([Config options, lines 139–174](https://agentclientprotocol.com/protocol/v1/session-config-options))

**Commands.** `available_commands_update` replaces the advertised list through `session/update`; each command requires `name` and `description`, with optional `input:{hint}`. ([Slash commands, lines 5–44](https://agentclientprotocol.com/protocol/v1/slash-commands); [lines 46–80](https://agentclientprotocol.com/protocol/v1/slash-commands)) Users invoke `/name …` as text in a normal `session/prompt`. ([Slash commands, lines 86–107](https://agentclientprotocol.com/protocol/v1/slash-commands))
